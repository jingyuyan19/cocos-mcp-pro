# Security Model

Cocos MCP Pro的目标不是承诺“永远不会出错”，而是缩小错误范围，并让关键写入可观察、可恢复。

## 信任边界

- 编辑器服务只监听本机回环地址。
- bridge通过工程临时目录中的随机握手令牌连接扩展。
- 对模型暴露会话NID，不把节点UUID作为主要操作接口。
- 资源路径以工程相对路径为主。
- bridge进程能够读取配置的工程目录，因此只应使用可信客户端配置和提示词。
- 本机回环连接只描述编辑器与bridge之间的通信。工具返回的层级、属性和日志交给AI客户端后，可能随上下文发送给所选云模型；是否离开本机取决于客户端、模型服务及其配置，插件不保证上下文全程留在本机。

## 写入护栏

- 属性写入受白名单约束。
- 组件删除支持`expectedComponentType`类型前置校验。
- 危险操作要求显式确认参数。
- 写操作不进行可能导致重复副作用的透明重试。

## 验证与恢复

- 关键写入会读取Creator运行态可观察结果，而不只信任离线JSON或单一“成功”回执。
- 对支持撤销且已核对执行结果和撤销目标的操作，可使用`cocos_mcp_undo_last`恢复。超时或断连不证明未执行；RC7的相关回执还可能包含误导性的`changed:false`。先只读核对，不能盲目重试或撤销，见[超时处理](./FAQ.md#rc7-timeout)。
- `cocos_diagnose`提供连接、日志、审计摘要和建议动作。

## 用户责任

在重要项目中仍应使用版本控制、备份和小步修改。不要把访问令牌、商业资产或未脱敏日志提交到公开Issue。
